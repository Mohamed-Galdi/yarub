# Student detail and tracking — Phase 4

### Student directory Excel export (2026-10-28)

The existing export button now includes 27 Arabic columns. The first three columns remain name, email and registration date. Added fields cover student ID, active/blocked status, email verification, last recorded practice activity, published course/lesson enrollment counts, test-attempt count and certificate count. For both القدرات and مهارات اللغة العربية, it exports participation, current available questions, unique answered questions, coverage percentage, first-attempt accuracy percentage, completed sessions, all recorded submissions including repeats, and last practice activity.

Progress uses the same `StudentTracking`/`ProgramMetrics` definitions as the directory and detail pages. Coverage excludes unavailable content; repeat answers do not inflate unique coverage. Unknown accuracy or unavailable coverage displays `غير متاح`. Enrollment counts follow the existing student-detail relationships; lesson counts do not certify an unexpired subscription. Last practice means recorded answers/completions, not last login. Filters, sorting, all matching pages, student-only scope and admin authorization are preserved. Aggregate enrollment counts are fetched in the export query without per-row relationship queries. Numeric values remain numeric (including zero); user text remains literal to prevent spreadsheet formulas. The RTL sheet has bold headings, filters and frozen headings/identity columns.

Completed 2026-10-25. Individual student tracking remains entirely inside **Users**. No production access, deployment, application-schema migration, or student-facing change occurred. Phase 5 has not begun.

## What changed

- Replaced the old student detail presentation with a compact avatar/name/status header, email, registration and last-practice dates, account actions, and state-preserving navigation. Blocked students remain inspectable. Blocking/restoring refreshes the profile and retains its URL state; native form redirects also retain section and list state.
- Added overview summaries and separate **القدرات** / **مهارات اللغة العربية** tabs. Each program shows per-type current coverage, first-answer accuracy when known, completed sessions, last practice, a type filter, and paginated session history. Arabic types correspond to the existing banks. Metrics reuse Phase 2 calculations rather than implementing another definition.
- Added HTML session reviews under the existing Users review route while preserving its JSON response for JSON clients. Reviews show saved prompts, options, selected/correct answers, textual results, explanations when present, and Qudrat reading passages. Arabic matching and partial credit use saved response/answer/point data. Unanswered questions remain distinct from incorrect answers. Opening a review does not call the student practice flow or update an attempt.
- Preserved courses, lessons, tests and certificates in a grouped learning-record area: subscription cost, monthly/annual plan, enrollment/expiry dates, test score and associated course/lesson, certificate date and original detail link. Expiry calculation no longer mutates the enrollment date. Missing enrollment dates show **غير متاح**. Lessons render independently of course enrollment.
- Loads only the selected section's records, paginated at 20, with eager loading for legacy associations. Counts remain visible without loading every legacy collection. Each section keeps its own page parameter; filters, review/back links and account actions preserve validated list/section state.

Main files: `app/Services/Admin/Tracking/{StudentDetail,StudentDetailState,SessionRecords}.php`, `app/Http/Controllers/Admin/{StudentController,StudentTrackingController}.php`, `resources/views/admin/students/{view-student,program,program-summary,session-review,arabic-review,legacy,account-menu,page-links,score}.blade.php`, `resources/views/components/admin/{student-coverage,tracking-time}.blade.php`, `resources/css/admin-student-detail.css`, and the focused Users runtime additions in `admin-users.css`, `users-admin.js`, and `layouts/admin.blade.php`.

## Data limits and next phase

Only stored submissions and snapshots support historical review. No historical completeness or tracking start date is invented. Missing/incomplete snapshots show **غير متاح**, without substituting edited current content. Current coverage can change with content availability; first-answer accuracy may include assistance. Arabic hint usage is not stored and is explicitly unavailable. Session scores retain each program's grading rules and are marked provisional for unfinished sessions. Zero/unknown denominators remain unavailable.

No additional tracking capture, table, index, or historical rewrite was necessary. Production-scale query-plan review, broader error/accessibility refinement and cross-page regression remain **Phase 5 — refinement and regression verification**, pending the user's instruction.
